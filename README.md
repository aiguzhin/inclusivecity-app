# InclusiveCity

Карта доступности Алматы: пешеходные маршруты, открытые данные OpenStreetMap
о доступности объектов и отчёты пользователей о барьерах (высокие бордюры,
сломанные пандусы и т.д.) с модерацией перед публикацией.

Готово к деплою «из коробки»: сервер написан на чистом Node.js **без единой
npm-зависимости**, поэтому не нужен даже `npm install` — только `node server.js`.

## Что внутри

- `public/index.html` — карта (Leaflet + тайлы OSM), построение маршрутов
  (OSRM), поиск мест (Nominatim), открытые данные о доступности (Overpass API).
  Все эти три сервиса — публичные, бесплатные и не требуют ключей.
- `public/admin.html` — панель модератора: одобрить / отклонить / удалить
  присланный отчёт о барьере.
- `server.js` — бэкенд: отдаёт статику и API для приёма/хранения отчётов
  (JSON-файл `data/reports.json` + фото в `uploads/`).

## Запуск локально

```bash
node server.js
```

Откройте http://localhost:3000 — карта. http://localhost:3000/admin — модерация
(токен по умолчанию `change-me-please`, **обязательно смените** через переменную
окружения `ADMIN_TOKEN` перед реальным использованием).

```bash
ADMIN_TOKEN=мой-секретный-токен PORT=3000 node server.js
```

## Деплой на Render (бесплатно, ~3 минуты)

1. Загрузите содержимое этой папки в новый репозиторий на GitHub (можно
   приватный).
2. Зайдите на https://render.com → **New** → **Web Service** → подключите
   репозиторий.
3. Параметры:
   - **Build Command**: оставьте пустым (зависимостей нет)
   - **Start Command**: `node server.js`
   - **Plan**: Free
4. В разделе **Environment** добавьте переменную `ADMIN_TOKEN` со своим
   секретным значением.
5. **Create Web Service** — через пару минут получите ссылку вида
   `https://inclusivecity-xxxx.onrender.com`.

В репозитории уже лежит `render.yaml` — Render может подхватить конфигурацию
автоматически при выборе **Blueprint**.

### ⚠️ Важно про хранение данных на бесплатном плане

Бесплатный план Render **не даёт постоянный диск** — при каждом передеплое
или перезапуске сервиса файлы `data/reports.json` и `uploads/` обнуляются.
Для MVP и демонстрации это некритично, но для реальной эксплуатации выберите
один из вариантов:

- Платный план Render с **Persistent Disk** (в `render.yaml` есть
  закомментированный пример — раскомментируйте и примонтируйте `data/` и
  `uploads/`).
- Деплой на **Railway** (https://railway.app) — там можно бесплатно
  подключить **Volume** и примонтировать его на `/app/data` и `/app/uploads`,
  данные переживут перезапуски.
- Переезд с JSON-файла на настоящую БД (например, бесплатный Postgres от
  Render/Neon/Supabase) — это следующий логичный шаг роста проекта.

## Деплой на Railway (альтернатива с постоянным хранилищем)

1. https://railway.app → **New Project** → **Deploy from GitHub repo**.
2. Railway сам определит Node.js и запустит `npm start`.
3. Добавьте переменную окружения `ADMIN_TOKEN`.
4. Во вкладке **Volumes** создайте том и примонтируйте на `/app/data` (и при
   желании второй — на `/app/uploads`), чтобы отчёты и фото не терялись между
   деплоями.
5. Во вкладке **Settings → Networking** сгенерируйте публичный домен.

## Как пользоваться панелью модерации

Откройте `<ваш-домен>/admin`, введите токен из `ADMIN_TOKEN`. Новые отчёты
приходят со статусом «на проверке» и не видны на публичной карте, пока вы их
не одобрите.

## Технические ограничения, о которых стоит знать

- Карта использует три внешних публичных API (тайлы OSM, Overpass, Nominatim,
  роутинг через routing.openstreetmap.de). Это open-source демо-серверы —
  бесплатные, но без SLA и с лимитами на частоту запросов. Для серьёзной
  нагрузки стоит поднять свой инстанс Overpass/Nominatim или подключить
  платный геосервис (например, Mapbox, Google Maps, 2ГИС API).
- Хранилище отчётов — простой JSON-файл. Подходит для сотен-тысяч записей;
  при росте нагрузки стоит перейти на Postgres/SQLite.
- Загруженные фото хранятся на диске сервера как есть, без сжатия/ресайза —
  при большом потоке отчётов стоит добавить оптимизацию изображения или
  переезд на объектное хранилище (S3-совместимое).
- ИИ-распознавание типа барьера по фото (упомянуто в интерфейсе) — задел на
  будущее, сейчас не реализовано: пользователь указывает тип вручную.
